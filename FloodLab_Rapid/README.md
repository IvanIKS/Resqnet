# FloodLab Rapid 0.1 / RESQNET

Дослідницький вебзастосунок для швидкої **сценарної оцінки** затоплення в довільній підтримуваній області. Окремий репозиторій, не заміна валідованого гідродинамічного solver-а. Вихідна обчислювальна сітка завжди 30 × 30 м, UTM; область до 250 000 комірок. Глобальне покриття не гарантовано: UTM широти, не перетинає антимеридіан, обмеження джерел і берегових зон.

## Запуск в Ubuntu 22.04 / WSL2

Розпакуй в окрему папку. В Ubuntu перейди туди (`cd /mnt/c/.../FloodLab_Rapid`). Зупини FloodLab v0.3 на порту 8000, якщо він ще працює.

```bash
bash run_linux.sh
```

Скрипт очищає `PYTHONPATH`/`PYTHONHOME` від ROS2, відключає автозавантаження pytest-плагінів, створює `.venv-linux`, встановлює залежності й запускає FastAPI. LISFLOOD-FP, CUDA, Node.js, компілятор C++ не потрібні. Відкрий http://127.0.0.1:8000. Якщо порт зайнятий, після активації venv запусти `python -m uvicorn rapid.app:app --host 127.0.0.1 --port 8001`.

Ручний запуск:

```bash
unset PYTHONPATH PYTHONHOME
export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
python3 -m venv .venv-linux
source .venv-linux/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
python -m uvicorn rapid.app:app --host 127.0.0.1 --port 8000
```

## Як користуватися

1. Натисни `Forlì офлайн` → `Розрахувати сценарій`. Потрібний лише встановлений Python; підкладка карти опціональна. Використовуються справжні DEM і еталонний GeoTIFF із попереднього запуску, а також об'єм ERA5 опадів зі звіту v0.2. Вологість, WorldCover та витрати річок в офлайн-пакеті відсутні. Не вигадані. Це неповний rain-only сценарій.
2. Натисни `Forlì онлайн` → `Розрахувати сценарій`. Координати, дати й еталон фіксовані як у попередньому експерименті. Самостійно завантажуються джерела, показуються запитані та повернені координати, історичні витрати, опади, вологість і статуси доступності. Еталон не використовується для вибору параметрів.
3. Для нової території обери `Найближчі 24–72 год` або `Історичний сценарій`, клікни по карті чи введи широту/довготу, розмір області 1–14 км та часовий горизонт. Час історичного сценарію UTC. До 250 000 клітинок на 30 м, деякі області 14 км можуть перевищити ліміт після проєкції.
4. Переглядай шари: середній, нижній/верхній сценарій, дощ, річковий сценарій, статичний JRC RP10, річки OSM, рельєф, еталон та карта похибок (якщо доступні). ZIP експорту містить GeoTIFF, PNG, JSON. Для довільного еталона завантаж бінарний GeoTIFF (1 затоплено, 0 перевірено сухо, NoData невідомо; якщо NoData відсутній, потрібно підтвердити повне покриття). Зображення підкладки OSM потребує мережі; локальні карти працюють без неї.

## Алгоритм

**Річкова частина**: Overpass знаходить річки, максимум 5 точок (доповнюються географічними точками); при відмові Overpass — 5 просторових точок без підтвердженої ідентичності русла. GloFAS автоматично запитує добову витрату за вибрані дати і попередню історію; ряди прив'язуються до тих самих повернених комірок. Використовуємо annual maxima з >=15 повних років і емпіричні plotting positions (n+1)/(n-rank+1). Без параметричної екстраполяції: вище історичного максимуму позначається цензурованою оцінкою n+1. Найбільше емпіричне RP серед точок — **регіональний сценарій**, не визначена частота для кожної річки. Для RP >=10 читаємо JRC карти двох сусідніх періодів; середній шар логарифмічно інтерполюється за RP, нижній/верхній — карти відповідних періодів. Це евристика, не фізична симуляція конкретної події. При RP <10 або невдалому запиті річковий компонент невідомий, а RP10 (якщо доступний) показується окремо як контекст. Перевищення історичного максимуму не обмежує реальну величину повені; інтервал не статистичний. QC маска сумнівних глибин виключає пікселі з річкового розрахунку, якщо доступна. Добова витрата не подається як об'єм переливу. GloFAS може вибрати іншу річку; точна прив'язка до upstream basin ще не реалізована.

**Дощова частина**: інтегруємо погодинні суми за точний період з урахуванням того, що сума відноситься до попередньої години. Погодні поля мають вихідну грубу роздільність; найближча повернена точка використовується для області. Вологість береться до початку події; попередні 72 год опадів зберігаються для діагностики. Простий коефіцієнт стоку (0.2–0.7 залежно від вологості, поправки на landcover, ±0.25 сценарний діапазон) — не калібрована інфільтрація. Якщо вологості немає, використовується явно умовний центр 0.45 (без поправок landcover), діапазон 0.2–0.7. Опади трактуються як рідина; немає снігової фізики. Priority-flood від відкритих меж знаходить пониження та D8 маршрути. Вода накопичується до рівня переливу, надлишок передається до наступного пониження або виводиться з області. Немає десятків тисяч часових ітерацій, швидкості потоку, часу прибуття, дренажу чи взаємодії річка–дощ. Це оцінка потенційного накопичення, а не стан на точний час спостереження.

**Об'єднання**: max(rain, river) на спільній 30-метровій сітці (не сума, щоб не подвоювати воду). JRC перепроєктується nearest-neighbor. Площа — комірки з >=0.05 м, 900 м² кожна; WorldCover клас 80 виключається з площі, якщо відомий. Якщо компонент відсутній, результат явно `partial_scenario`; невідома річка не означає відсутність повені. `coverage_complete.tif` відображає, де обидва компоненти і потрібні дані доступні, а не ймовірність або впевненість. Сценарні межі не є довірчим інтервалом. Немає валідованої глобальної точності. Не використовувати для евакуації/оперативного оповіщення без незалежної перевірки.

## Продуктивність

Паралельний збір незалежних даних через ThreadPoolExecutor; важка фізична інтеграція часу вилучена. Priority-flood є переважно послідовним; це не багатопотоковий гідродинамічний solver. Локальний кеш растрових вікон 7 днів, історичні JSON 30 днів, оперативні JSON 15 хв; кеш створюється в `.cache/`, можна видалити. Жодних глобальних локальних баз. Окремий subprocess для кожного завдання, максимум 2 одночасні, жорсткий ліміт 120 с з моменту запуску worker: при перевищенні — явна помилка, а не нескінченне очікування. Повний online час залежить від зовнішньої мережі, квот, GDAL/VRT, розміру й кешу. Немає SLA.

Реальний офлайн тест Forlì: 153 216 комірок, 30 м. Дощова оцінка близько 2.2 с включно з PNG/GeoTIFF (час залежить від машини), IoU 0.11075, F1 0.19942, прогнозована площа в області еталона 12.3894 км², еталон 12.0717 км², recall 0.2020. Старий v0.2: IoU 0.16326, F1 0.28069, 440.68 с на комп'ютері користувача; v0.3 з Green-Ampt та відкритими межами: IoU 0.01195, 1128.87 с. Це **не рівнозначне порівняння часу на одному обладнанні чи доказ поліпшення точності**: інша модель/параметри, offline без мережі, попередня симуляція кінцевого стану. Краще співвідношення площ не означає кращої просторової точності. Річковий сценарій не протестовано на справжніх API через DNS-обмеження середовища. У тестах його перевірено на контрольованій підміні даних.

## Перевірки / API

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q` — 10 автоматичних тестів: збереження маси при заповненні понижень, відтік, NoData, точне часове інтегрування опадів, RP, фіксована сітка, реальний офлайн Forlì, контрольоване об'єднання річкової/дощової частин, відсутній API, HTTP job + TIFF/ZIP export. `node --check static/app.js` — синтаксис JS. Повний браузерний тест не проведено. Живі API в середовищі розробки недоступні (DNS). Інтеграції написані за опублікованими схемами, потребують перевірки на ПК.

FastAPI Swagger: http://127.0.0.1:8000/docs. `POST /api/jobs` multipart `config` JSON та опційний `reference` TIFF; `GET /api/jobs/{id}` стан/звіт; `GET /api/jobs/{id}/download` ZIP. Приклад:

```bash
curl -F 'config={"mode":"demo"}' http://127.0.0.1:8000/api/jobs
```

Зовнішній production deployment ще не готовий: авторизація, контроль квот користувачів, обмеження RAM/диску, TTL результатів, багатокористувацька безпека, легальний комерційний доступ до API та незалежна валідація потрібні до публічного запуску. Не виставляй цей локальний прототип в Інтернет без доопрацювання.
